# Guide: ANTLR + Java project for the Lua interpreter

This guide was tested: the grammar parses all of `test_cases/*.in` with 0
syntax errors.

## 0. What you already have

- `lib/antlr-4.13.2-complete.jar` is the ANTLR tool and runtime in one jar.
- `grammar/LuaLexer.g4` and `grammar/LuaParser.g4` are the grammars.
- `src/Main.java` is a placeholder, and `out/` is the output folder.
- Java 26 is installed, so nothing else is needed.

Ignore `grammar/.antlr/`. It is generated by the VS Code ANTLR extension.

## 1. Add the base class the lexer needs

The lexer grammar declares `superClass = LuaLexerBase` and calls
`HandleComment()` and `IsLine1Col0()` from it. Without this class the
generated code will not compile. Create it in `src/`.

**`src/LuaLexerBase.java`**

```java
import org.antlr.v4.runtime.*;

public abstract class LuaLexerBase extends Lexer {
    protected LuaLexerBase(CharStream input) { super(input); }

    // Called right after '#': true only if it was the first char of the file.
    public boolean IsLine1Col0() { return _input.index() == 1; }

    // Called right after '--': consumes the rest of the short or long comment.
    public void HandleComment() {
        if (_input.LA(1) == '[') {
            int i = 2, level = 0;
            while (_input.LA(i) == '=') { level++; i++; }
            if (_input.LA(i) == '[') {                       // --[==[ ... ]==]
                for (int k = 0; k < i; k++) getInterpreter().consume(_input);
                while (_input.LA(1) != IntStream.EOF) {
                    if (_input.LA(1) == ']') {
                        int j = 2, l = 0;
                        while (_input.LA(j) == '=') { l++; j++; }
                        if (l == level && _input.LA(j) == ']') {
                            for (int k = 0; k < j; k++) getInterpreter().consume(_input);
                            return;
                        }
                    }
                    getInterpreter().consume(_input);
                }
                return;
            }
        }
        while (_input.LA(1) != IntStream.EOF && _input.LA(1) != '\n' && _input.LA(1) != '\r')
            getInterpreter().consume(_input);                // short comment
    }
}
```

The parser used to need a `LuaParserBase` class too, for the
`IsFunctionCall()` predicate. It was dropped when `prefixexp` was rewritten
with direct left recursion (see the README), so only the lexer base class is
needed now.

## 2. Generate the lexer and parser

Run from the project root. Generate the lexer **and** the parser, lexer first,
and run it from inside `grammar/`. Generating the parser alone fails with
`cannot create implicit token for string literal`, because
`tokenVocab = LuaLexer` needs `LuaLexer.tokens` to exist.

```bash
cd grammar
java -jar ../lib/antlr-4.13.2-complete.jar -Dlanguage=Java -visitor -no-listener -o ../gen LuaLexer.g4 LuaParser.g4
cd ..
```

This creates `gen/` with `LuaLexer.java`, `LuaParser.java`,
`LuaParserVisitor.java` and `LuaParserBaseVisitor.java`.

- `-visitor` generates the visitor classes, a good fit for a tree-walking
  interpreter.
- `-no-listener` skips the listener classes, which are not needed.

## 3. Write `Main.java`

Reads the file as ISO-8859-1 (one byte per char), as described in `scope.md`.

```java
import org.antlr.v4.runtime.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;

public class Main {
    public static void main(String[] args) throws Exception {
        CharStream input = CharStreams.fromPath(Paths.get(args[0]), StandardCharsets.ISO_8859_1);
        LuaLexer lexer = new LuaLexer(input);
        LuaParser parser = new LuaParser(new CommonTokenStream(lexer));
        var tree = parser.chunk();               // 'chunk' is the start rule
        System.out.println("syntax errors: " + parser.getNumberOfSyntaxErrors());
        if (args.length > 1) System.out.println(tree.toStringTree(parser));  // optional debug dump
    }
}
```

## 4. Compile and run

```bash
CP=lib/antlr-4.13.2-complete.jar
javac -cp $CP -d out gen/*.java src/*.java
java  -cp out:$CP Main test_cases/01.in          # add a second argument to print the parse tree
```

The jar is needed on the classpath at compile time and at run time, because it
contains the ANTLR runtime. The separator is `:` on Linux and `;` on Windows.

## 5. The development loop

| You changed | Re-run |
|---|---|
| a `.g4` file | step 2, then step 4 |
| only a `.java` file | `javac ...` and `java ...` from step 4 |

A small `build.sh` keeps this to one command:

```bash
#!/usr/bin/env bash
set -e
CP=lib/antlr-4.13.2-complete.jar
rm -rf gen out && mkdir gen out
(cd grammar && java -jar ../$CP -Dlanguage=Java -visitor -no-listener -o ../gen LuaLexer.g4 LuaParser.g4)
javac -cp $CP -d out gen/*.java src/*.java
```

Then: `./build.sh && java -cp out:lib/antlr-4.13.2-complete.jar Main test_cases/01.in`

## 6. Housekeeping

- Add `gen/` and `grammar/.antlr/` to `.gitignore`, since they are generated.
- The `*.jar` rule in `.gitignore` also ignores `lib/antlr-...jar`, so
  teammates must download it:
  `https://www.antlr.org/download/antlr-4.13.2-complete.jar`
- Everyone must use the same ANTLR version (4.13.2) for generating and running.
  Generated code and the runtime must match.

## 7. Next step: the interpreter

Create `LuaInterpreter extends LuaParserBaseVisitor<Object>` and override the
`visitXxx` methods. The alternatives of `stat`, `exp`, `prefixexp`, `var`,
`functioncall` and `field` are labeled, so there is one method per alternative
(`visitWhileStat`, `visitAddExp`, `visitMethodCallExp`, ...) instead of a single
`visitStat`/`visitExp`.
In `Main`, replace the tree dump with `new LuaInterpreter().visit(tree)`.
